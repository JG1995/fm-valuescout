# 0010 — pnpm

## Status

Accepted

## Context

Node projects need a package manager for dependencies and scripts. CI uses Node 24. The template should pick one manager, pin it, and document install steps for clean machines (including WSL Ubuntu).

## Decision

Use **pnpm** as the package manager. Pin the version in `packageManager` in `package.json`. Document `pnpm install`, `pnpm dev`, and `pnpm build` as primary workflows.

Target **Node.js 24** for local dev and CI (`.github/workflows/check.yml`).

## Alternatives considered

### npm

npm ships with Node and needs no extra install. pnpm is faster on large trees and uses a strict `node_modules` layout that reduces phantom dependency bugs.

### yarn (Berry)

yarn is mature with workspace support. pnpm is equally capable for solo repos with simpler defaults for many developers in 2026.

### bun

bun is fast as runtime and installer. Ecosystem compatibility with Vite, Vitest, and TanStack tooling is still catching up compared to Node + pnpm. Higher risk for a stability-focused template.

## Consequences

### Positive

- Fast installs and disk-efficient store.
- `packageManager` field enables Corepack version pinning.
- Aligns with modern React open-source defaults.

### Negative

- Developers must enable Corepack or install pnpm — not only `npm install`.
- Some corporate environments default to npm-only policies.
